Tutorial for FHIR Implementation Guides with FHIR Shorthand (FSH) Language

This tutorial is a hands-on guide for building FHIR Implementation Guides using FHIR Shorthand (FSH) language. It covers everything from foundational FHIR concepts through five practical exercises with solutions, ending with the generation of a complete IG using sushi and the IG Publisher.

Introduction to FHIR

Fast Healthcare Interoperability Resources (FHIR) represents HL7's current standard addressing data exchange difficulties between diverse health information systems. The specification adapts to new architectural paradigms and web development technologies, distinguishing it from predecessors like HL7 v2 and CDA.

Organisations adopting FHIR for interoperability improvement include both private companies and public institutions. A notable recent initiative is HL7 Europe's work supporting the European Health Data Space (EHDS).

Anatomy of a FHIR Implementation Guide

An FHIR Implementation Guide comprises documentation, resources, and examples addressing specific healthcare use cases. It has three fundamental elements:

  1. Documentation — written in Markdown format
  2. FHIR Profiles — in JSON or XML format; special resources that validate agreed FHIR structures and terminology bindings
  3. Example FHIR resources — adapted to the established profiles

The HL7 FHIR Genomics Reporting Implementation Guide is a good reference example of this structure, standardising the exchange of genetic information data.

🔗 Full registry of FHIR implementation guides: fhir.github.io/auto-ig-builder/builds.html

FHIR Implementation Guide Generation

Guides follow standardised templates via the IG Publisher tool, an open-source utility maintained by the FHIR community. This tool generates deployment-ready webpages from the three fundamental components.

🔗 Official Publisher documentation: IG Publisher CLI

FHIR Profiles in Implementation Guides

"The FHIR profile is the most important element of an implementation guide. It defines the syntactic and semantic structure of a dataset for the specific use case."

Profiles allow you to constrain and extend FHIR resources to meet the specific requirements of your use case. 🔗 Matchbox FHIR resource validation tutorial: ahdis.github.io/matchbox/validation-tutorial/

FHIR Shorthand Language

FHIR Shorthand (FSH) is a domain-specific language for defining FHIR profiles, extensions, value sets, and instances. It enables management of implementation guides as proper software projects.

Specifically, FSH:

  • Reduces the complexity of working with raw JSON/XML
  • Enables CI/CD methodologies and source control
  • Operates cross-platform

🔗 FSH specification: build.fhir.org/ig/HL7/fhir-shorthand
🔗 FSH School (official learning resource): fshschool.org
🔗 FSH Online (browser-based tool): fshonline.fshschool.org
🔗 FSH finder (registry): fshschool.github.io/fsh-finder/

Practical Exercises

The tutorial includes five exercises covering all the key FSH concepts. Each has working solutions hosted

Exercise 1 — Create an FHIR Profile

Define a MyPractitioner profile with sliced identifiers supporting License Number, passport, and national ID types. Concepts covered: profile definition, field requirements, slicing.

Exercise 2 — FHIR Profiles with Terminologies

Create a SNOMED value set with specialty codes (Cardiology, Pediatric Oncology, Medical Oncology) and bind it to the qualification field. Concepts covered: value sets, bindings, terminology validation vs. sushi validation.

Exercise 3 — Customize Profile with Extensions

Create an extension capturing practitioner years of experience and link it to the profile. Concepts covered: extension creation, extension linking, extension reuse.

Exercise 4 — Create Profile from Inherited Profile

Start from the International Patient Summary (IPS) Patient profile and create MyPatient requiring language, gender, name, and birthdate. Concepts covered: profile inheritance, parent specification maintenance.

Exercise 5 — Customize with Invariants

Identify and implement invariants from the IPS Patient profile. Key insight: invariants use FHIRPath and must be validated with the FHIR Validator — not sushi — to be properly checked. Concepts covered: invariants, FHIRPath, validator distinction.

Building a Full IG with FSH

Once you have your FSH files, you can generate a complete FHIR Implementation Guide:

sushi init
cd ExampleIG
./_updatePublisher.sh
./_genonce.sh

Navigate to the /output/ folder and open index.html in a browser to view the generated guide. To add new resources, place .fsh files in input/fsh/ and run ./_genonce.sh again.

Installation requirements:
  • IG Publisher CLI installation
  • Sushi installation
